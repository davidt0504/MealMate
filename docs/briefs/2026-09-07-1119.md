# Brief -- 2026-09-07 -- Initial architecture map

Opening signpost. This is the initial architecture brief for Meal Mate, the repository whose consumer product is Kimatta.

System shape. The app is an Android-first Flutter surface over a Rust core. Flutter owns screens, navigation, accessibility, transient state, and platform file sharing. Rust owns household and food rules, deterministic planning, SQLite, backup validation, and every durable mutation. Generated flutter_rust_bridge code connects them with task-sized calls.

Startup signpost. Dart initializes the native library and mounts one Riverpod scope. Database health opens a process-wide Rust connection. Household bootstrap follows, and all feature providers select that household identity. The app routes a new household through Welcome and starts idempotent starter installation without blocking entry.

Core behavior. Recipes retain structured ingredients and their original text. Planning uses household-defined civil-date cycles. Pantry is a binary mark, not a stock audit. Shopping is derived conservatively: compatible known quantities combine, while uncertain contributions remain separate and explainable.

Planner signpost. Cover My Week loads one immutable snapshot, applies hard constraints before scoring, runs a deterministic bounded beam search, grades coverage without overstating certainty, and produces attention requests. Preview, declined apply, successful apply, and explicit user corrections are recorded in an immutable controller ledger. Applying changes and recording evidence share a transaction.

Safety boundaries. User locks and hard vetoes cannot be bought through by softer preferences. Flutter never receives a database handle. Generated bindings are not hand-edited. Cloud sync, production auth, public sharing, billing, production signing, and iOS packaging are future gates, not hidden current dependencies.

Coverage signpost. The report accounts for all 240 tracked files across seven subsystem pages. There are 225 text files and 15 binary assets, with no symlinks, submodules, Python parse failures, uncovered paths, or duplicate page assignments.

Working tree signpost. The roadmap was modified but uncommitted when this report started. That WIP is recorded as context only. No architecture page relies on it as committed evidence.

Closing signpost. Start with the system overview, then follow either the Flutter path for user behavior or the Rust path for durable rules and planning. The bridge and storage page explains where those paths meet.
